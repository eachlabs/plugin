# Contributing

How this repository is laid out, how the skills are generated and how a
version is released.

## Repository layout

| Path | Contents |
| --- | --- |
| `.claude-plugin/plugin.json` | Plugin manifest |
| `.claude-plugin/marketplace.json` | Marketplace listing this plugin, for Add marketplace |
| `.mcp.json` | The connector URL, `https://mcp.eachlabs.ai/mcp` |
| `CHANGELOG.md` | What each version changes |
| `LICENSE` | MIT |
| `skills/<name>/SKILL.md` | The skills, generated by `scripts/convert-skills.mjs` from `eachlabs/skills` |
| `skills/DEFERRED.md` | Source skills not converted, with the reason |
| `scripts/` | Conversion and check scripts |

## Skills

Do not edit `skills/` by hand. A daily job (`.github/workflows/sync-skills.yml`)
regenerates them from `eachlabs/skills` and opens or updates one pull request
when they change; it can also be started by hand from the Actions tab. To
regenerate locally:
`node scripts/convert-skills.mjs --source <checkout of eachlabs/skills>`. To
check the result: `node scripts/check-skills.mjs`, and
`node --test scripts/convert/test/*.test.mjs` for the converter.

## How to release

1. Put one `version/patch`, `version/minor` or `version/major` label on the pull request.
2. The `version` workflow writes that version into `plugin.json` and `CHANGELOG.md` on the branch.
3. Merging tags the merge commit `vX.Y.Z`.

A pull request that changes `skills/`, `.mcp.json`, `.claude-plugin/`, `hooks/` or
`commands/` fails without exactly one of those labels, because Claude updates an
installed plugin only when its version changes. The daily skills sync labels its
pull request `version/patch`.
